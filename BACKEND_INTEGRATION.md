# Backend Integration Guide

This guide describes how to implement the backend server and APIs required by the frontend application.

## 1. Authentication Integration
The frontend auth module expects a cookie-based authorization flow utilizing JWT tokens.

### Endpoint: `POST /api/auth/login`
- **Request Payload:**
  ```json
  {
    "email": "admin@vtltravel.com",
    "password": "adminpassword"
  }
  ```
- **Expected Success Response:**
  ```json
  {
    "success": true,
    "token": "YOUR_JWT_ACCESS_TOKEN_HERE"
  }
  ```
- **Cookie Setup:**
  Upon successful login, the frontend will write the token to a cookie named `admin_token`.
  Make sure your backend expects this token in the headers:
  ```http
  Authorization: Bearer <YOUR_JWT_ACCESS_TOKEN_HERE>
  ```

## 2. Hotels CMS Endpoints
The backend must support standard CRUD endpoints for hotels under the prefix `/api/hotels`. All modifying operations (`POST`, `PUT`, `DELETE`) should be protected by your Admin auth middleware.

### 2.1 Get All Hotels
`GET /api/hotels`
- **Expected Response:**
  ```json
  [
    {
      "id": 1,
      "title": "Holiday Inn Resort Batam",
      "stars": "4 ★",
      "starNum": 4,
      "image": "https://images.unsplash.com/photo-1571896349842-33c89424de2d?auto=format&fit=crop&w=1100&q=80",
      "price": "$87",
      "priceNum": 87,
      "available": true,
      "facilities": ["Free Wi-Fi", "Swimming Pool"],
      "gallery": ["https://url1.jpg", "https://url2.jpg"],
      "description": "Hotel description..."
    }
  ]
  ```

### 2.2 Get Hotel by ID
`GET /api/hotels/:id`
- **Expected Response:**
  Returns a single hotel object matching the schema above, including nested `rooms` list:
  ```json
  {
    "id": 1,
    "title": "Holiday Inn Resort Batam",
    ...
    "rooms": [
      {
        "id": 101,
        "name": "SUPERIOR ROOM, 1 King Size Bed, City View",
        "bedInfo": "1 King size bed(s)",
        "capacity": "3 pers. max",
        "size": "32m²",
        "tags": ["City View", "Bathtub/shower combination"],
        "price": "$87.00",
        "publicRate": "$95.00",
        "taxes": "$12.00",
        "roomsLeft": "Only 1 room left",
        "image": "https://url.jpg"
      }
    ]
  }
  ```

### 2.3 Create Hotel
`POST /api/hotels`
- **Request Payload:**
  Same schema as Hotel (without the `id` field, which should be generated by your database).

### 2.4 Update Hotel
`PUT /api/hotels/:id`
- **Request Payload:**
  Updated hotel schema values.

### 2.5 Delete Hotel
`DELETE /api/hotels/:id`
- **Expected Response:**
  `{ "success": true, "message": "Hotel successfully deleted" }`

## 3. Frontend Configuration to Switch
Once your backend APIs are ready:
1. Set the following environment variables in your `.env` file at the project root:
   ```env
   VITE_API_BASE_URL=http://localhost:5000/api
   VITE_USE_MOCK_API=false
   ```
2. The Axios client ([axiosInstance.js](file:///c:/Users/rakib/vtltravel/src/api/axiosInstance.js)) will automatically read the `VITE_API_BASE_URL` and send authorization interceptors with Bearer tokens to your server.
3. The services ([hotelService.js](file:///c:/Users/rakib/vtltravel/src/api/services/hotelService.js) and [authService.js](file:///c:/Users/rakib/vtltravel/src/api/services/authService.js)) will switch off mock localStorage mode and make HTTP requests to your server.
